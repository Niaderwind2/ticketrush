Lab 2 : le tournoi des mutants

L'IA écrit des tests en quelques secondes. La couverture grimpe. Mais ces tests détectent-ils vraiment une erreur ? Le mutation testing répond : il introduit des bugs dans le code et regarde si vos tests les voient.

Le principe

Stryker modifie le code, une petite erreur à la fois : un >= devient >, un + devient -, une constante change. Chaque version modifiée est un mutant.

  • Si un test échoue, le mutant est tué : vos tests ont vu l'erreur.
  • Si tous les tests passent, le mutant survit : vos tests n'auraient pas vu ce bug.

Le score de mutation est la part de mutants tués. C'est une mesure bien plus honnête que la couverture.

1. Mesurer le point de départ (5 min)

Le module src/TicketRush.Domain/Pricing.cs calcule les prix. Il n'a qu'un test, qui passe.

cd tests/TicketRush.UnitTests
dotnet tool restore
dotnet stryker

Notez le score affiché pour Pricing.cs, puis ouvrez le rapport HTML : chaque mutant survivant y est montré dans le code.

2. Faire écrire les tests par l'IA (10 min) IA 2 · assistant

Donnez Pricing.cs à votre assistant et demandez-lui des tests xUnit. Collez-les dans PricingTests.cs, vérifiez qu'ils passent, puis relancez Stryker.

Annoncez votre score au formateur : il est reporté au tableau.

3. Le tournoi (25 min)

Objectif : tuer le plus de mutants survivants possible. À la main, ou en guidant l'IA avec le rapport Stryker. Pour chaque mutant tué, notez dans un fichier notes.md :

  • le mutant (ligne, modification) ;
  • pourquoi le test de l'IA ne le voyait pas ;
  • ce que l'IA ne pouvait pas savoir sans vous (une règle métier, une frontière).

Rappel des règles métier : contexte TicketRush.

Palier avancé · Les frontières

Le early bird commence-t-il à 30 jours pile, ou au-delà ? Les frais à 4 billets sont-ils de 6 € ou plafonnés ? Écrivez un test par frontière, avec la valeur exacte attendue.

Palier expert · Les mutants qu'il vaut mieux laisser vivre

Certains mutants survivants ne valent pas un test : le texte d'un message d'erreur, par exemple. Lesquels ? Configurez Stryker pour les ignorer (stryker-config.json) et justifiez ce choix comme vous le feriez dans une stratégie de test.

4. Débrief (5 min)

Les trois meilleurs scores expliquent leur méthode en deux minutes. À titre de repère, la branche lab-2-solution atteint 87,5 % : les seuls mutants survivants modifient des messages d'erreur.

À retenir : la couverture dit quelles lignes ont été exécutées, pas ce qui a été vérifié. Un test sans assertion précise couvre tout et ne prouve rien. Quand l'IA écrit vos tests, le mutation testing devient votre contrôle qualité.
